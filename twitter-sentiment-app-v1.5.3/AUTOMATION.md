# Automatic collection

The hourly planner uses one shared queue. A scheduler wakes it at minutes 7, 22, 37 and 52. Hourly jobs are unique, and repeat wakes do not rebuy completed jobs. Daily counts remain a comparable snapshot. On-demand Premium refreshes share cache and quota (five per member/day, thirty across the site/day). Collection stays behind Vercel Authentication.

Deploy `ops/collector-workflow.yml` to the repository root as `.github/workflows/tradersecho-collector.yml` on the default branch. Add repository Actions secrets `TRADERSECHO_URL`, `TRADERSECHO_CRON_SECRET`, and `TRADERSECHO_VERCEL_BYPASS`. The latter is the existing project-scoped Vercel automation token. Neither the X token nor database credentials are sent to GitHub. Only trusted repository maintainers should be allowed to change workflows. Run the workflow once and verify the heartbeat in Administration before calling automation active.

GitHub schedules can be delayed and public repositories can have schedules disabled after inactivity; the app shows an overdue heartbeat after 90 minutes. GitHub's workflow failure notifications provide the operational alert. No browser or local computer must stay open once the hosted schedule is enabled.

Suggested initial plan: 357 daily count queries, top ten hourly counts, up to 480 posts/day shared by rotating hot stocks, tracked accounts and demand samples, 32 profile lookups/day, 30 demand count requests/day. Maximum planned cost for 31 days is $181.51 at the checked X rates, before retries/taxes/hosting. Monthly reservations stop at $185; provider limits remain authoritative. The monthly gate can halt a plan after failures or usage changes. Increasing the universe to 1,000 at these frequencies does not fit this budget.

Each hour one popular stock is sampled (rotating within top ten), plus one group of up to five tracked handles. With five handles each is queried hourly; with 25, groups rotate about every five hours. Account queries include posts without cashtags, but ticker attribution requires a recognized cashtag. Search results are capped at ten per request and may omit posts. Links open the original X post. Cached author identities avoid repeated profile charges. Post reads, failed/uncertain requests and profile reads have transactional daily and monthly reservations. Raw attention counts remain susceptible to bots; sentiment screening applies only to sampled posts.

Retries: transient network failures, 429 and 5xx receive a 15-minute delay and at most three attempts. Authentication/credit/validation errors require operator review. Failed/uncertain purchases retain reservations. Hourly jobs older than two hours are expired instead of replaying an expensive backlog. Daily history backfills only the recent six days. Stored counts older than that remain available. Collection leases prevent overlapping scheduler runs.

The frontend refreshes cached data every minute while visible and shows explicit failures instead of waiting forever. Administrative collection status refreshes every 15 seconds. Neither refresh starts a paid X request. The initial backfill writes hourly buckets in a pipelined batch.
